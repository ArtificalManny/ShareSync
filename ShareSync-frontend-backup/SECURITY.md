# Security Policy

## Supported Versions

We release patches for security vulnerabilities for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take security seriously at ShareSync. If you discover a security vulnerability, please follow these steps:

### 1. DO NOT create a public GitHub issue

Security vulnerabilities should be reported privately.

### 2. Email us directly

Send details to: **security@sharesync.com**

Include:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)

### 3. Give us time to respond

- We'll acknowledge your email within 48 hours
- We'll send a detailed response within 7 days
- We'll work on a fix and keep you updated

### 4. Responsible Disclosure

Please give us reasonable time to fix the issue before public disclosure. We'll credit you in our security advisory (unless you prefer to remain anonymous).

## Security Best Practices

When contributing to ShareSync:

- Never commit sensitive data (API keys, passwords, tokens)
- Use environment variables for configuration
- Sanitize user input
- Follow OWASP guidelines
- Keep dependencies up to date

## Bug Bounty Program

We currently do not have a paid bug bounty program, but we deeply appreciate security researchers who help us keep ShareSync safe. You'll be:

- Credited in our Hall of Fame
- Mentioned in release notes
- Eligible for ShareSync swag

## Questions?

For security-related questions, contact: security@sharesync.com

Thank you for helping keep ShareSync and our users safe! 🔒
